# JobFlow AI

An AI-powered personal job management workspace: save any job post (text, PDF, screenshot, URL), let AI turn it into a structured job card with a deadline, and manage the whole application pipeline in one place.

**Status: planning complete, implementation not started.**
Nothing in this repository is application code yet. The full product blueprint lives in [`docs/`](./docs).

## Planned stack (verified latest stable)

- **Frontend:** Next.js 16.3 (App Router, `src/proxy.ts`, Turbopack) · React 19 · TypeScript · Tailwind 4 · shadcn/ui · TanStack Query 5 · Zustand 5
- **Backend:** Laravel 13 (PHP 8.3+) · REST `/api/v1` · Sanctum · Horizon · Reverb · Pest
- **Database:** PostgreSQL 16 (+ `pgvector` for semantic search)
- **AI:** Laravel AI SDK (`laravel/ai` 1.0) with OpenAI primary → Gemini failover
- **Storage:** Cloudflare R2 (private bucket, signed URLs)
- **Contract:** OpenAPI generated by Scramble → TypeScript types consumed by the frontend

## Repository layout (decided: two repositories)

| Repo | Contents | Deploy |
|---|---|---|
| **`jobflow-api`** — this repository | Laravel 13 API at the repo root + this `docs/` blueprint | VPS/Forge → `api.jobflow.ai` |
| **`jobflow-web`** — new repository | Next.js 16 app (`src/`) | Vercel → `app.jobflow.ai` |

```
jobflow-api/   # this repository — Laravel application root (app/, config/, routes/, tests/) + docs/
jobflow-web/   # separate repository — Next.js application root (src/)
docs/          # this blueprint, versioned with the API repo (single source of truth)
```

Contract flow: this repo's CI publishes an `openapi.json` artifact → the web repo's CI regenerates `src/types/api.d.ts` from it, so a backend rename fails the frontend build.
